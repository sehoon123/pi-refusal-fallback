# pi-refusal-fallback

[English](README.md) · [CI](https://github.com/sehoon123/pi-refusal-fallback/actions/workflows/ci.yml)

Pi에서 제공자 거절 응답이 발생하면 **사용자가 지정한 순서대로 다른 모델에 재요청**하는 확장입니다.

**특정 제공자나 모델을 기본값으로 넣지 않았습니다. 설정하지 않으면 자동 fallback은 비활성입니다.** 처음 사용하는 모델은 평소처럼 Pi에서 선택하고, fallback 모델은 각자의 환경에 맞게 직접 지정합니다. 각 제공자의 정책과 인증·이용 제한은 그대로 적용됩니다.

## 설치

```sh
pi install git:github.com/sehoon123/pi-refusal-fallback@v0.5.0
```

이미 실행 중인 세션은 `/reload` 하세요. 기존 단일 파일 `refusal-fallback.ts`를 사용했다면 패키지와 **동시에 로드하지 마세요.** 패키지로 전환할 때 기존 파일을 자동 로드 디렉터리 밖으로 옮겨야 합니다.

Node.js 22.19 이상 및 actionable `agent_before_settle`을 지원하는 Pi가 필요합니다. 자동 테스트 대상은 Pi 1.2.0과 1.4.0입니다. Pi가 제공하는 모듈을 사용하며 별도 런타임 npm 의존성은 없습니다.

## 모델 설정

가장 쉬운 방법은 내장 편집기입니다. Pi 터미널 UI나 pi-web에서 실행하세요.

```text
/refusal-fallback setup
```

```text
Fallback model setup   ● unsaved changes
[Models]  Order (2)   Options   Review
Filter: son▌   2/63
→ [1]   ica-example/claude-sonnet
  [ ]   other-example/sonnet-large
  ↑ 0 above · ↓ 0 below · 1/2

Order: claude-sonnet → gpt-large
type to filter · ↑↓ move · Enter add/remove · Tab/←→ section · Ctrl+S save · Esc cancel
```

| 위치 | 키 |
|---|---|
| Models | 입력해서 검색(`/model`과 같은 퍼지 검색) · `↑↓` `PgUp` `PgDn` `Home` `End` 이동 · `Enter` 추가/제거 · `Esc` 검색어 지우기 |
| Order | `Enter`로 항목을 집고 `↑↓`로 위치를 바꾼 뒤 `Enter`로 놓기, `Esc`로 이동 취소 · `Del`/`Backspace`/`x` 제거 |
| Options | `Enter` 또는 `Space`로 스위치 전환·선택지 순환, 목록 아래에 현재 항목 설명 표시 |
| Review | 최종 순서와 저장 위치 확인 · `Enter` 저장 |
| 어디서나 | `Tab`/`Shift+Tab` 또는 `←→` 섹션 이동 · `Ctrl+S` 저장 · `Esc` 취소(변경이 있으면 두 번) · `Ctrl+C` 즉시 중단 · 마우스 휠 스크롤, 클릭 선택 |

화면은 **현재 설정 순서**에서 시작하고, 일시적으로 사용할 수 없는 항목은 직접 제거하기 전까지 보존합니다. 강조된 행 주변의 제한된 창만 그리므로 모델 수가 아무리 많아도 정상적으로 스크롤됩니다. 사용자 정의 컴포넌트를 지원하지 않는 클라이언트는 한 번에 최대 7개 항목만 보여주는 페이지 방식 메뉴를 사용합니다.

직접 파일을 편집하려면 아래 방법을 사용하세요.

시작 모델은 `/model` 또는 `pi --model ...`로 선택합니다. 이 확장은 사용자가 지정한 fallback 목록만 사용하며 제공자·인증정보를 생성하거나 모델 ID를 임의로 바꾸지 않습니다.

### 개인 설정 파일

`<agent-dir>/refusal-fallback.json`을 만드세요. 기본 위치는 `~/.pi/agent/refusal-fallback.json`입니다.

```json
{
  "chain": [
    { "provider": "your-first-provider", "id": "your-first-fallback-model" },
    { "provider": "your-second-provider", "id": "your-second-fallback-model" }
  ]
}
```

위 값은 추천 모델이 아니라 **교체해야 하는 자리표시자**입니다. `pi --list-models`에서 실제 제공자와 모델 ID를 확인하고 순서대로 적으세요. 목록을 늘리거나 줄일 수 있으며 두 모델로 제한되지 않습니다.

- `PI_CODING_AGENT_DIR`를 지정했다면 해당 agent 디렉터리에 설정합니다.
- `PI_REFUSAL_FALLBACK_CONFIG=/absolute/path/to/config.json`으로 다른 파일을 사용할 수 있습니다. 상대 경로는 Pi 작업 디렉터리 기준이며 `~/`도 지원합니다.
- 최상위 필드는 `chain`, 선택적 boolean UI 옵션, `carryPartial`입니다. 각 모델 항목에는 비어 있지 않은 `provider`, `id` 문자열만 허용합니다.
- `{"chain": []}`는 자동 fallback을 비활성화합니다. 중복 모델은 순서를 유지하며 한 번만 정규화합니다.
- 파일·환경변수는 64 KiB, 체인은 최대 128개 항목, 모델 식별자는 1,024자로 제한합니다. 잘못된 UTF-8, 특수 파일, 과도한 입력은 원문을 출력하지 않고 거절합니다.
- 설정 파일은 설치된 패키지 저장소 밖에 보관하세요. 업데이트로 개인 설정이 덮어써지지 않습니다.
- 실행이 끝난 뒤 `/refusal-fallback reload`로 파일만 재적용할 수 있습니다. 전체 `/reload`도 지원합니다.

[설정 예제](examples/refusal-fallback.example.json)도 제공합니다.

### 환경변수

```sh
export PI_REFUSAL_FALLBACK_CHAIN='your-provider/your-model-a,other-provider/organization/your-model-b'
pi
```

쉼표로 순서를 구분하고 **첫 번째 `/`만** 제공자와 모델의 구분자로 사용합니다. 따라서 모델 ID 내부의 추가 `/`는 보존됩니다. 잘못된 항목을 조용히 무시하거나 기본 모델로 대체하지 않습니다.

빈 환경변수는 설정 파일보다 우선하여 fallback을 끕니다.

```sh
PI_REFUSAL_FALLBACK_CHAIN='' pi
```

환경변수는 Pi를 시작한 프로세스에 설정되어 있어야 합니다. 다른 터미널에서 export해도 이미 실행 중인 Pi의 환경은 바뀌지 않습니다.

### 우선순위와 상태 확인

1. `PI_REFUSAL_FALLBACK_CHAIN` — 빈 값도 우선합니다.
2. `PI_REFUSAL_FALLBACK_CONFIG`로 선택한 파일.
3. 기본 `<agent-dir>/refusal-fallback.json`.
4. 설정 없음 — 비활성.

기본 파일이 없는 것은 정상입니다. 명시적으로 선택한 파일이 없거나 설정이 잘못된 경우 fallback만 비활성화하고 오류를 안내합니다. 일반 Pi 요청은 계속 사용할 수 있습니다.

TUI 및 대화상자를 지원하는 RPC 클라이언트에서 다음 명령을 사용합니다.

```text
/refusal-fallback status
/refusal-fallback reload
/refusal-fallback setup
```

- **status**: 현재 체인·등록 누락·인증 상태, 조용한 모드 여부와 최근 실행 결과·건너뛴 이유·소요 시간·모델 복원 결과를 표시합니다. 모델 요청이나 파일 변경은 없습니다.
- **reload**: idle 상태에서 설정만 재적용합니다. 진행 중인 실행은 시작 시의 설정을 유지합니다. 새 설정이 잘못됐다면 이후 자동 전환을 안전하게 비활성화합니다.
- **setup**: 위 편집기입니다. 원자적으로 저장하고 새 파일은 `0600`, 기존 파일은 `.bak`으로 보존하며 기본값이 아닌 UI 옵션만 기록합니다. 재시작 없이 다음 요청부터 적용되고, 변경이 없으면 쓰지 않습니다. 취소하면 쓰지 않습니다. 같은 런타임의 겹치는 설정 창, 환경변수에 가려지는 파일 저장, 심볼릭 링크·특수 파일 덮어쓰기를 막습니다. 별도 프로세스의 동시 저장은 원자적 마지막 저장 우선입니다.

탭 자동완성은 세 하위 명령을 제안하며, 하위 명령을 끝까지 입력하면 첫 번째 `Enter`로 바로 실행됩니다.

### 진행 표시와 조용한 모드

```json
{
  "chain": [],
  "retryMessages": false,
  "showStatus": true,
  "notifications": true
}
```

위 빈 체인은 모델을 직접 추가하기 전까지 비활성입니다. 세 UI 옵션은 생략하면 모두 `true`입니다.

- `retryMessages: false`: 한 줄 재시도 안내를 대화 화면에서 숨깁니다. 이 안내는 설정과 관계없이 **모델에 전송되지 않으므로** 답변이나 토큰 비용에 영향이 없습니다.
- `showStatus`: fallback이 실행되는 동안 `fallback 2/3: requesting model-id` 같은 상태를 표시하고, 정상 완료·복원되면 지웁니다. 체인 소진·모델 변경·복원 실패는 다음 실행 전까지 쉬운 문장으로 남깁니다. 같은 상태는 재전송하지 않습니다.
- `notifications`: 체인 소진 등의 일반 경고를 제어합니다. 중요한 설정·복원 실패는 항상 알립니다.

최근 실행 요약은 프롬프트·응답·인증정보 없이 비컨텍스트 세션 메타데이터로 저장합니다. `/reload` 후에도 활성 분기의 최근 요약을 복구할 수 있습니다.

## 끊긴 출력 전달 (partial output handoff)

거절로 응답이 중간에 끊기면 그 응답에서 이미 보인 부분(추론·답변)은 기본적으로 **버려지고**, 다음 모델이 이전 대화 전체를 받아 그 응답을 처음부터 다시 만듭니다. 끊긴 출력을 넘기는 것은 선택 사항입니다.

```json
{ "chain": [], "carryPartial": "cross-provider" }
```

| `carryPartial` | 동작 |
|---|---|
| `off` (기본) | 아무것도 넘기지 않습니다. |
| `cross-provider` | 다음 모델의 provider id가 끊긴 모델과 **다를 때만** 넘깁니다(`ica-a/x` → `ica-b/y`). |

**같은 공급자에는 절대 넘기지 않습니다.** 게이트웨이 실측에서 Claude의 답을 Claude에 다시 넘기자 “모델 출력 복제”로 차단되었고(2회 중 2회, 출력 전), 같은 프롬프트를 노트 없이 보낸 경우는 14회 모두 정상 응답했습니다. 같은 공급자는 같은 내용에 같은 안전 검사도 적용합니다. 0.4.0의 `always` 값은 경고와 함께 `cross-provider`로 읽으며(fallback은 계속 동작), setup에서 한 번 저장하면 파일이 정리됩니다.

`/refusal-fallback setup` → **Options**에서 고를 수 있고, 화면에 각 값의 설명이 표시됩니다.

넘기는 것: **화면에 보이는** 추론(Claude는 표시되는 요약이며 숨겨진 원본이 아닙니다)과 부분 답변 텍스트. 가려진(redacted) 추론, 공급자 전용 서명 추론 블록, 실행되지 않은 도구 호출은 넘기지 **않으므로** 다음 모델이 어떤 작업을 할지 스스로 결정합니다. 추론 8,000자·답변 4,000자까지이며 최신 부분을 남기고 잘린 곳을 표시합니다.

넘기는 방식: 실제 대화 뒤에 `[Notes from an interrupted earlier attempt]` 라벨의 사용자 역할 메시지 하나를 붙이고, **신뢰할 수 없는 참고 자료이며 지시가 아니다**, 위 요청에 대한 완전한 답을 하라고 안내합니다. 본문 속 구분자는 무력화하여 자기 섹션을 닫지 못합니다.

- **바로 다음 응답에만.** 이후 단계(예: 도구 호출 뒤)와 이후 프롬프트에는 반복하지 않으며, 여러 번 이어져도 가장 최근 중단분만 유지합니다.
- **저장하지 않음.** 요청 시점에만 메모리에서 만들며 세션에 기록하지 않아 pi-web이나 내보낸 세션에 나타나지 않습니다(끊긴 응답 자체는 평소처럼 저장됩니다).
- **역효과면 철회.** 노트를 받은 모델이 아무것도 쓰기 전에 거절하면, 체인을 넘어가기 전에 같은 모델을 노트 없이 **한 번** 다시 시도하므로 출력을 넘겨서 답을 놓치는 일이 없습니다.
- 노트를 넘기면 화면 안내에 표시(`Its partial output is passed along as notes (…)`)되고, `/refusal-fallback status`에서 모드와 사용 횟수를 볼 수 있습니다.

**공급자 약관을 확인하세요.** 한 공급자의 출력을 다른 서비스에 넘기는 것은 사용자의 결정이며, 일부 공급자는 출력 재사용을 제한합니다. 선택한 fallback 공급자는 대화에 더해 이 노트도 받습니다. 그래서 기본값이 `off`입니다.

## 동작과 제한

- terminal assistant의 명시적 `rawStopReason: "refusal"` 또는 좁게 정의한 제공자 거절 오류만 감지합니다. `ECONNREFUSED`, 프록시·인증 거절, 일반 정책 문구는 모델 거절로 오인하지 않습니다. pending·중단·도구 실행 메시지는 자동 전환하지 않습니다.
- 오류 경로에서 무시될 수 있는 `turn_end` 재시작 대신, `agent_before_settle`에서 실제 후속 요청을 시작합니다.
- 실패한 assistant 응답은 `context_edit`으로 후속 모델 컨텍스트에서만 제외합니다. 원본 이력과 사용량은 유지합니다. 어느 모델이 거절했고 어느 모델로 재시도하는지 알리는 한 줄 안내(`↻ a/b declined this request. Retrying with c/d (fallback 1).`)는 화면에만 남기며 `context` 훅으로 모든 모델 요청에서 제외합니다. 실제 요청 뒤에 가짜 사용자 메시지가 붙어 원래 요청을 가리는 일이 없습니다. Pi가 거절된 응답에 붙이는 붉은 오류 줄은 Pi의 기본 표시이며 안내보다 먼저 나타납니다.
- 현재 모델·중복 모델·이미 시도한 모델은 다시 시도하지 않습니다. 등록되지 않았거나 인증할 수 없는 모델은 건너뜁니다.
- 설정한 체인을 소진하면 마지막 거절을 남기고 멈춥니다. 무한 반복하지 않습니다.
- 중단된 요청은 재시작하지 않습니다. 완료·중단 후 원래 모델과 thinking을 복원하되 사용자가 도중에 선택한 새 모델·thinking을 덮어쓰지 않습니다. 비동기 전환 중의 선택 경쟁도 제한된 복원으로 처리하고, 실패하면 명확하게 안내합니다. 전역 기본값은 바꾸지 않습니다.
- 새 사용자 실행에서는 체인 상태를 초기화합니다.
- 일반 성공이나 무관한 인증·할당량·네트워크 오류를 자동 전환 사유로 취급하지 않습니다. Pi 자체 재시도 정책은 별개입니다.
- 다른 확장의 선행 경계 항목과 이미 요청한 continuation을 존중합니다. 재요청할 사용자·도구 컨텍스트가 없다면 입력을 만들어 넣지 않고 멈춥니다. 별도의 제공자·라우팅 확장은 백엔드 가용성과 thinking 옵션에 영향을 줄 수 있습니다.

### 성능

설정 읽기는 시작·명시적 reload/setup 때만 수행합니다. 토큰이나 각 turn마다 파일을 읽지 않습니다. 중복 정규화와 충돌 없는 모델 키로 중복 조회·재시도를 막습니다. 호환용 오류 문구는 앞의 4,096자만 검사하며, 타이머·백그라운드 폴링·별도 모델 호출·토큰별 스트림 핸들러를 만들지 않습니다. 상태는 실행 경계에서만 갱신하며 같은 값은 재전송하지 않습니다. 조용한 모드는 안내 메시지에 의한 프롬프트 증가를 없앱니다.

## 개인정보·비용·로그

fallback 제공자도 마지막 질문뿐 아니라 대화 컨텍스트를 받을 수 있습니다. 개인정보, 데이터 보관 위치, 비용, 이용약관 및 권한에 맞는 모델을 직접 선택하세요. 게이트웨이 접근 제한·모델 가용성·할당량을 우회하지 않습니다.

API 키·쿠키·요청 본문·프롬프트·응답 본문을 저장하거나 디버그 로그에 남기지 않습니다. 디버그 로그는 선택적으로 모델 ID와 실행 흐름만 기록합니다.

```sh
PI_REFUSAL_FALLBACK_DEBUG=1 pi
```

위치는 `<agent-dir>/refusal-fallback.log`이고 새 파일 권한은 `0600`입니다. 로그 기록 실패는 요청을 중단시키지 않으며 설정 오류에 입력 원문을 포함하지 않습니다.

## 개발 및 검증

```sh
npm ci --ignore-scripts
npm run check
npm test
npm run test:e2e   # 전용 tmux 서버에서 실제 pi TUI를 실행, tmux가 없으면 건너뜀
npm pack --dry-run
```

138개 자동 테스트는 메모리 기반 인증정보·모델 목록과 로컬 HTTP 서버만 사용하므로 실제 API 키나 유료 요청이 필요 없습니다. 설정 크기·우선순위, 원자적 저장·백업·취소, 연속 전환·소진, 조용한 모드, 진행·요약 표시, 수동 모델 선택 경쟁, 복원 실패, 다른 확장과의 협력, 컨텍스트 보존, 서로 다른 API 간 전환을 검사합니다.

실제 `pi -p`와 비공개 게이트웨이로도 실제 거절 후 전환, 연속 두 번 fallback의 3회 반복, 체인 소진을 확인했습니다. 다중 전환 반복에서는 실제 API 응답 뒤 테스트용 거절 이벤트를 주입했습니다. 개인 제공자·모델 선택, 인증정보, 세션 원본 및 실호출 증적은 공개 저장소에 포함하지 않습니다. 특정 모델이나 게이트웨이의 가용성을 보장하는 것은 아닙니다.
